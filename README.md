# AI-обзвон клиентов САТ — Node.js

MVP исходящих голосовых звонков через **Twilio Voice + OpenAI Realtime API** с двумя ключевыми функциями:

1. пользователь загружает базу клиентов в Excel (`.xlsx`);
2. любые сведения о продукции агент получает только из каталога `https://www.satpricep.by/catalog/filter/clear/apply/`.

## Как работает

```text
Excel клиентов
     ↓
Веб-панель /campaigns/upload
     ↓
Проверка номеров и согласия
     ↓
Обновление каталога satpricep.by
     ↓
Кэш data/catalog-knowledge.json
     ↓
Исходящий звонок Twilio
     ↓
OpenAI Realtime Agent
     ↓
search_catalog → только подтверждённые фрагменты satpricep.by
```

Перед каждым новым вопросом клиента о продукции агент обязан вызвать `search_catalog`. Если подтверждённого факта в каталоге нет, агент должен сообщить, что не нашёл его в подтверждённых данных сайта, и предложить зафиксировать вопрос для менеджера. Он не должен угадывать цену, наличие, массу, объём, комплектацию и другие характеристики.

## Excel

Готовый файл `clients-template.xlsx` лежит в корне проекта и доступен из веб-панели.

Обязательные колонки:

- `Телефон` — E.164, например `+375291234567`;
- `Имя`;
- `Согласие` — `Да`, `Yes`, `true`, `1`;
- `Источник согласия`.

Необязательные:

- `Компания клиента`;
- `Продукт`;
- `Цель звонка`;
- `Комментарий`.

Строки без подтверждённого согласия не запускаются в обзвон.

## Установка

```bash
cp .env.example .env
npm install
npm start
```

Откройте:

```text
http://localhost:5050/
```

На странице:

1. введите `CALL_API_KEY`;
2. загрузите `.xlsx`;
3. проверьте отклонённые строки;
4. при необходимости нажмите «Обновить каталог сейчас»;
5. запустите обзвон.

До реального теста оставьте:

```env
DRY_RUN=true
```

## Актуальность каталога

По умолчанию знания считаются свежими 6 часов:

```env
CATALOG_MAX_AGE_HOURS=6
REQUIRE_FRESH_CATALOG=true
```

При старте кампании сервис сначала пытается обновить сайт. Если обновление невозможно и `REQUIRE_FRESH_CATALOG=true`, обзвон не начнётся. Это сделано специально, чтобы агент не продавал продукцию по неподтверждённой или устаревшей информации.

Сервис индексирует страницы каталога и пытается открыть карточки отдельных товаров. Если карточка защищена антибот-проверкой, в индекс остаётся подтверждённый текст карточки из страницы каталога; ничего не генерируется автоматически.

## API

### `POST /campaigns/upload`

Multipart upload Excel. Заголовок:

```text
x-api-key: CALL_API_KEY
```

Поле файла:

```text
file
```

### `POST /campaigns/:id/start`

Перед стартом проверяет свежесть каталога, затем запускает кампанию.

### `GET /campaigns/:id`

Статус кампании.

### `GET /catalog/status`

Показывает дату и размер локальной базы знаний.

### `POST /catalog/sync`

Принудительно обновляет знания с satpricep.by. Требует `x-api-key`.

### `POST /calls`

Одиночный звонок, оставлен для интеграции с CRM.

## Результаты

- `data/catalog-knowledge.json` — подтверждённые данные каталога и URL источников;
- `data/campaigns/<id>.json` — состояние загруженной кампании;
- `data/call-results.jsonl` — результаты разговоров;
- `data/calls/<CallSid>.json` — история Realtime-сессии;
- `data/do-not-call.json` — стоп-лист.

## Важные ограничения

- Фраза «агент отвечает на все вопросы» не должна означать «агент всегда знает ответ». Если на сайте нет факта, безопасный и корректный ответ — сообщить об отсутствии подтверждения и передать вопрос менеджеру.
- Сам сайт является динамическим внешним источником и может изменить HTML/антибот-защиту. Перед production нужно добавить мониторинг успешности синхронизации каталога.
- Для production следует заменить локальные JSON/Map на PostgreSQL и Redis, добавить очередь звонков, роли пользователей, аудит изменений базы знаний и CRM-интеграцию.
- Перед автоматическим рекламным обзвоном необходимо проверить требования законодательства к согласию, рекламе, записи разговора и обработке персональных данных для конкретной страны.
